# Security Policy

## Supported version

Only the latest `main` development version is supported before the first release.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Send a minimal reproduction, affected file/version, and impact to the repository maintainer through the private contact listed by the published repository owner.

Do not include real API keys, personal data, or copyrighted product files. The project should run offline by default and must not execute untrusted product content.
